Instrução CP, registrador SREG e desvios condicionais

Altere os operandos de 8 bits e observe como o processador calcula os flags e determina quais desvios BRxx são verdadeiros. Todas as condições são avaliadas independentemente para fins de ensino.

R17 — segundo operando

Operação interna da comparação

CP R16, R17 ⇢

A CPU realiza uma subtração de 8 bits para atualizar os flags. Os conteúdos de R16 e R17 não são modificados.

Todos os bits do SREG

Ordem dos bits do registrador de status: I T H S V N Z C. A instrução CP altera H, S, V, N, Z e C; I e T são preservados. Defina seus valores anteriores abaixo.

H — empréstimo do bit 3 para o bit 4
S — sinal corrigido: N ⊕ V
V — overflow aritmético com sinal
N — bit 7 do resultado
Z — resultado igual a zero
C — empréstimo na subtração de 8 bits
I — habilitação global de interrupções (inalterado)
T — bit de transferência (inalterado)

Resultado dos oito desvios após o CP

Atenção: várias condições podem ser verdadeiras ao mesmo tempo, mas, em um programa real, um desvio tomado modifica o PC e impede a execução dos desvios posteriores daquela sequência.

Equações usadas pelo simulador

Sejam a = R16, b = R17 e r = (a − b) mod 256. Na subtração AVR:

Z = (r == 0)
N = bit7(r)
V = (bit7(a) ⊕ bit7(b)) ∧ (bit7(a) ⊕ bit7(r))
S = N ⊕ V
C = (a < b)   [operandos unsigned]
H = ((a & 0x0F) < (b & 0x0F))
I e T = valores anteriores (CP não os modifica)

O flag N reflete apenas o bit mais significativo do resultado; não equivale à comparação menor com sinal. Para isso utilize S = N ⊕ V, que é a condição de BRLT.

Referência técnica: Microchip AVR Instruction Set Manual — CP (Compare), SREG e instruções BRxx. Este simulador representa os flags após CP; não executa firmware nem emula o ciclo completo de instruções.
